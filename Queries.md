# Запросы проекта

## 1. Определение запросов

Для работы проекта определено 17 запросов: 12 неагрегирующих и 5 агрегирующих. Запросы используют нормализованную схему из 28 таблиц. Новые таблицы и атрибуты не добавляются.

Двоеточие обозначает входной параметр запроса. Выходные атрибуты указаны по именам столбцов результата.

### Правила выборок и расчётов

- Период включает обе границы. В 1.1 и 1.10 ревизия должна быть выпущена строго после `:after_date`.
- Участок - пара «трубопровод + объект». Компонент относится к нему через спул, ревизию и чертёж. Соединение и его ремонт учитываются на участке один раз, если хотя бы один компонент находится на нём. Итоги разных участков могут пересекаться.
- В 1.4 дата - сварка или сборка; приёмка отражается статусом. В 1.5 - компоненты и оборудование без утеплителя и покрытия. Оборудование связано только с объектом, его материал не хранится.
- Поставщик компонента определяется через поставку, оборудования - напрямую. В 1.7 пара «объект + поставщик» не повторяется. В 1.6 строка соответствует компоненту и документу поставки; без документа его поля равны `NULL`. Статус доставки не определяется.
- Стажёр не имеет записей о сертификатах; истёкший сертификат категорию не меняет. В 1.2 проверяются стандарт и `valid_until >= :as_of_date`, без истории действия.
- Выпущенные спулы имеют статус `released`, `installed` или `tested`. В 1.8 исключается спул с любым пакетом `passed`. Строка соответствует паре «спул + пакет», без пакетов поля пакета равны `NULL`.
- Ремонты объединяются из двух таблиц: соединение определяется через проверку либо напрямую. В 1.9 незавершённые статусы - `planned`, `in_progress`; `NULL` не включается. В 2.5 учитываются только `completed` с датой в периоде.
- В 1.10 сравниваются используемая и последняя ревизии одного чертежа по номеру; последняя выпущена после `:after_date`. Одна строка - спул. Дата его выпуска не используется; переделка не подразумевается.
- Пакет относится к объекту через спулы, компоненты фланцевых соединений или оборудование. В 1.11 пакет `passed` выводится по объекту один раз.
- В 2.1 показаны текущие статусы; объект без спулов получает количество 0 и статус `NULL`. История выпуска спулов не хранится.
- В 2.2 суммируются известные массы спулов, пропуски считаются отдельно. Без спулов масса равна 0; если все массы неизвестны - `NULL`. Компоненты итог не умножают.
- В 2.3 выводятся все 12 месяцев; считаются пакеты `passed` и `failed` с датой в выбранном году. Повторные попытки отдельно не хранятся.
- В 2.4 при равных положительных диаметрах диаметр прибавляется один раз на соединение. Остальные случаи отражаются в `unresolved_diameter_count`; без определяемого объёма сумма равна `NULL`. Группировка - по сварщику и двум диаметрам; сварщики без работ выводятся с количеством 0. Каждому участнику засчитывается полный объём; итоги сварщиков не складываются.

### Готовность к финальным испытаниям

В 1.12 пакет испытаний готов, если:

1. Статус - `planned`, состав непустой.
2. Все включённые спулы - `installed` или `tested`.
3. Все включённые фланцевые соединения - `accepted`.
4. Всё включённое оборудование - `installed`.
5. Все ремонты сварных соединений компонентов включённых спулов - `completed`.
